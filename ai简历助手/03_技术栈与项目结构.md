# AI 智能简历优化平台 —— 技术栈与项目结构

本文件严格基于项目源码实现进行提炼，真实反映系统的全栈技术选型、系统架构、模块分层、API 接口及数据库设计。

## 一、技术栈全景

### 1. 后端技术栈
- **核心框架**：`FastAPI 0.115.0`（基于 ASGI 规范的高性能异步 Python Web 框架）
- **Web 服务器**：`Uvicorn 0.34.0`（轻量级、高并发 ASGI 服务器）
- **ORM / 数据持久化**：`SQLAlchemy 2.0.36`（声明式 2.0 映射模式）+ `Alembic 1.14.0`（数据库版本迁移）
- **数据验证与序列化**：`Pydantic 2.10.0` + `email-validator 2.3.0`（强类型入参/出参 Schema）
- **认证与安全**：`python-jose 3.3.0`（JWT 令牌签发与校验）+ `passlib[bcrypt] 1.7.4`（密码加盐哈希）
- **HTTP 客户端**：`httpx 0.28.0`（异步非阻塞 HTTP 库，用于外部 LLM 与 OCR API 调用）
- **多模态与文档导出**：`python-docx 1.1.2`（HTML 结构化转换为 Word 文档）+ `Pillow 11.0.0`（图片校验与预处理）
- **测试框架**：`pytest 9.1.1` + `pytest-asyncio 1.4.0`

### 2. 前端技术栈
- **架构模式**：单页应用 (Single Page Application, SPA)
- **核心语言**：原生 `JavaScript ES6+`（模块化、异步 Fetch API）
- **UI 渲染与样式**：`Tailwind CSS`（原子化 CSS 引擎，磨砂玻璃科技感暗黑主题设计）
- **图标系统**：`Lucide Icons`（现代矢量图标库）
- **前端路由**：自研 Hash 路由引擎（支持带参导航与页面激活状态联动）
- **富文本容器**：安全沙箱 `iframe` 容器（隔离渲染优化后高保真 HTML，杜绝样式污染）

### 3. 数据库
- **存储引擎**：`SQLite 3`（轻量级嵌入式关系型数据库，生产可无缝切换至 PostgreSQL/MySQL）
- **连接管理**：SQLAlchemy SessionLocal + 连接池，支持事务原子性回滚

### 4. AI 与大模型集成
- **协议标准**：`OpenAI Chat Completions` 兼容协议（DashScope Compatible Mode）
- **默认模型**：`qwen3.7-max`（文本优化、预检与微调）、`qwen-vl-max`（图片简历 OCR 解析）
- **Prompt 策略**：系统角色约束、Few-Shot 少样本注入、STAR 原则重构模板、结构化 JSON 输出解析

## 三、核心模块与架构设计

系统采用经典 **分层架构 (Layered Architecture)** 设计，前后端严格解耦：

```mermaid
graph TD
    User["Web 客户端 (SPA / Tailwind CSS)"] -->|HTTP / RESTful API| Router["FastAPI 控制器层 (routers/)"]
    Router -->|依赖注入 (Auth / DB)| Sec["安全与认证 (utils/security.py)"]
    Router -->|DTO 校验| Schema["Pydantic 数据模式 (schemas/)"]
    Router --> Service["业务服务层 (services/)"]
    Service -->|ORM / SQL| DB[("SQLite 数据库 (SQLAlchemy)")]
    Service -->|异步调用 / httpx| LLM["大语言模型 API (DashScope / OpenAI)"]
    Service -->|视觉识别 / OCR| VL["多模态视觉模型 (qwen-vl-max)"]
    Service -->|文档生成| Docx["Word 转换引擎 (python-docx)"]
```

### 核心业务执行链（以简历深度优化为例）：
1. **认证拦截**：从 Header 提取 Bearer JWT Token，校验用户有效性。
2. **点数校验与预扣**：开启数据库事务，检查钱包余额（≥1 点），执行扣减并记录流水（保持事务开放）。
3. **知识检索 (Context Enrichment)**：基于目标岗位 JD 和简历文本，检索相关的“行业最佳实践”与“优化案例”，组装上下文。
4. **LLM 异步推理**：调用大模型进行 STAR 重构、数据量化与评分生成。
5. **安全清洗 (XSS Sanitization)**：使用白名单标签消毒输出的 HTML 文本。
6. **知识自动沉淀**：从优化成果中异步提取高质量模式与关键词，存入知识库待审。
7. **事务统一提交**：全部成功后统一 `db.commit()`；若任意环节失败，事务自动回滚并退回点数。

### 1. `users`（用户表 · 9 个字段）
- `id` (INT, PK, AUTO_INCREMENT)
- `username` (VARCHAR 50, UNIQUE, NOT NULL, 索引)
- `email` (VARCHAR 100, UNIQUE, NOT NULL, 索引)
- `password_hash` (VARCHAR 255, NOT NULL)
- `avatar_url` (VARCHAR 255)
- `is_active` (BOOLEAN, DEFAULT TRUE)
- `last_login`, `created_at`, `updated_at` (DATETIME)

### 2. `resumes`（简历档案与优化表 · 19 个字段）
- `id` (INT, PK, AUTO_INCREMENT)
- `user_id` (INT, FK -> `users.id`, 索引)
- `title` (VARCHAR 100, NOT NULL)
- `original_text` (TEXT, NOT NULL)
- `optimized_text` (TEXT)
- `target_city` (VARCHAR 50), `target_salary` (VARCHAR 50), `target_jd` (TEXT), `extra_details` (TEXT)
- `model_used` (VARCHAR 100)
- `status` (VARCHAR 20, DEFAULT 'pending', 索引)
- `version` (INT, DEFAULT 1), `parent_id` (INT, FK -> `resumes.id`)
- `tags` (TEXT), `optimization_score` (FLOAT)
- `star_rewrites` (INT, DEFAULT 0), `quantifications` (INT, DEFAULT 0), `keywords_matched` (INT, DEFAULT 0)
- `created_at` (DATETIME, 索引)

### 3. `knowledge_entries`（知识库条目表 · 14 个字段）
- `id` (INT, PK, AUTO_INCREMENT)
- `category` (VARCHAR 50, NOT NULL, 索引) —— `industry_practice` / `resume_template` / `optimization_case` / `jd_keyword`
- `title` (VARCHAR 200, NOT NULL, 索引)
- `content` (TEXT, NOT NULL)
- `source` (VARCHAR 50, DEFAULT 'manual') —— `manual` / `auto_extract`
- `resume_id` (INT, FK -> `resumes.id`, 可选)
- `industry` (VARCHAR 50), `job_title` (VARCHAR 50), `tags` (TEXT)
- `status` (VARCHAR 20, DEFAULT 'active', 索引) —— `active` / `review_needed` / `archived`
- `usage_count` (INT, DEFAULT 0), `effectiveness` (FLOAT, DEFAULT 0.0)
- `created_at`, `updated_at` (DATETIME)

### 4. `user_wallets`（用户钱包表 · 7 个字段）
- `id` (INT, PK, AUTO_INCREMENT)
- `user_id` (INT, FK -> `users.id`, UNIQUE, 索引)
- `balance` (INT, DEFAULT 0, CHECK balance >= 0)
- `total_recharged` (INT, DEFAULT 0), `total_consumed` (INT, DEFAULT 0)
- `created_at`, `updated_at` (DATETIME)

### 5. `point_transactions`（点数收支流水表 · 8 个字段）
- `id` (INT, PK, AUTO_INCREMENT)
- `user_id` (INT, FK -> `users.id`, 索引)
- `amount` (INT, NOT NULL)
- `balance_after` (INT, NOT NULL)
- `type` (VARCHAR 20, NOT NULL, 索引) —— `recharge` / `consume` / `refund` / `gift`
- `description` (VARCHAR 200, NOT NULL), `reference_id` (VARCHAR 100)
- `created_at` (DATETIME, 索引)

### 6. `payment_orders`（充值订单表 · 9 个字段）
- `id` (INT, PK, AUTO_INCREMENT)
- `order_no` (VARCHAR 50, UNIQUE, NOT NULL, 索引)
- `user_id` (INT, FK -> `users.id`, 索引)
- `amount_cents` (INT, NOT NULL), `points` (INT, NOT NULL)
- `status` (VARCHAR 20, DEFAULT 'pending', 索引) —— `pending` / `paid` / `cancelled` / `expired`
